# 보고서 작업 규칙 (2026-09 보고서 오너 지적 200여 건에서 뽑음)

각 규칙은 실제로 한 번 이상 틀려 오너가 되짚은 것이다.
작업 시작·구현·검수·착지 단계마다 해당 절을 읽고 그대로 따른다.
새 규칙을 더하면 이미 처리한 같은 유형 항목에도 소급해 다시 돌린다(MUST).

## 1. 작업 시작·소통

- 요청마다 작업 워크트리를 `git fetch` 후 `origin/feature` 와 비교하고, 뒤처졌으면 받은 뒤 시작한다(MUST).
  여러 세션이 같은 feature 에 착지하므로 옛 코드 위에서 고치면 이미 바뀐 차트를 되돌린다.
- 보고는 오너가 쓰는 언어로 한다. 범위·서버·브랜치·커밋·폭·개수와 미확인 항목을 함께 적는다(MUST).
- 오너 지적은 저장소 밖 로컬 기록(지적 트래커 + 반성문: 지적→사실→반성→보강)에 남기고,
  보강 항목은 MUST/SHOULD 문장으로 써서 이 플러그인에 옮긴다. 플러그인 저장소는 공개이므로
  티켓 번호·고객 자료·내부 채널 이름은 옮기지 않는다(MUST).
- 외부와 공유하는 문서(데이터 요청표·메일·고객 전달 자료)에 내부 이슈 번호·링크·트래커 이름을 쓰지 않는다.
  다 쓴 뒤 그 키워드로 검색해 0건을 확인한다(MUST). 받는 쪽이 사무직이면 개발 용어 없이 합쇼체로 쓴다.
- 데이터를 다시 요청하기 전에 원본 값의 자릿수를 직접 센다: 부동소수 오차를 걷어 내고(`'%.10f' % v`)
  **기간별** 분포를 본다. x.0 이 고르게 섞인 것은 정상, 특정 기간에 몰린 정수는 그 기간만 반올림된 것이다.
  다른 데이터인지 반올림인지는 PDF 그림의 선 좌표를 값으로 보정해 대조한다(MUST).
- 외부 링크(PDF·영상·첨부)는 규칙으로 추정해 넣지 않는다. 실제로 열어 쪽수·제목·첫 줄을 확인하고,
  없는 이름으로도 요청해 서버가 아무 파일이나 돌려주지 않는지 본다(MUST).

## 2. 기준 출처

- 원본 확인은 DOCX 원문 단위 전수로 한다: 장별 횟수, 표 셀 행렬·병합, 각주 앞 문맥, 그림별 제목·자료·주,
  이미지 전수, 목차 id 의 DOM 존재. 전역 문자열 포함 여부로 통과시키지 않는다(MUST).
- 원문→화면만 보지 말고 화면→원문(화면에만 남은 옛 보고서 문구)도 본다. 첫 화면(인포그래픽·영상 자막·탭)도 범위다.
  DOCX 안에서 그림인 인포그래픽 글자는 PDF 로 만들어 대조한다.
- 오너가 "기존 구현 참조"라 하면 같은 보고서의 선례부터 찾고 파일명을 보고에 적는다. 이전 보고서 도너는 그다음이다(MUST).
- 규칙·경로·의도·데이터 의미를 추정으로 채우지 않는다. 이전 보고서 실측, 공용 헬퍼, 원본 셀이 근거다(MUST).

## 3. 차트 구현

- 색·축 제목·경계선·음영·툴팁·x축 날짜 형식·2패널은 공용 헬퍼와 상수만 쓴다. 하드코딩하지 않는다(MUST).
- Highcharts 기본값을 명시한다: 막대 `borderRadius: 0`(chart 가 아니라 plotOptions.column 에),
  누적 순서 `reversedStacks`, scatter·arearange `lineWidth: 0`. 병합 후 실제 적용값을 런타임에서 확인한다.
- 원본이 이어진 선은 `connectNulls: true`. 분기 자료를 월 축에 얹을 때 필수다.
- 음영을 넓히려고 축 min/max 를 늘리지 않는다. 밴드의 `to` 만 플롯 끝까지 늘린다. 데이터 없는 칸이 보이면 실패다.
- category 축의 연도 경계·연간·분기 막대의 음영 경계는 칸 사이(`i - 0.5`, 막대 사이)다. 날짜 값은 막대 가운데다.
- 막대 폭은 원본 그림의 "칸 대비 비율"로 맞춘다. 고정 폭(`pointWidth`) 대신 최대 폭(`maxPointWidth`)과 간격 보장을 쓰되,
  간격 보장 훅이 원본 비율보다 가늘게 깎지 않는지 폭별로 잰다(MUST). 원본에서 겹친 막대는 `grouping: false` 다.
- 미러 우축(`linkedTo`)은 부모 축과 같은 눈금·같은 여백이어야 한다. `linkedTo` 는 `tickPositions` 를 복사하지 않는다.
- responsive 규칙의 `yAxis`·`series` 배열은 1:1 로 적용돼 빠진 축·계열을 지운다. 모든 축·계열 수만큼 적는다(MUST).
- `isDoubleChart` 2패널은 데스크톱에서도 패널 폭이 400 미만이라 `maxWidth: 400` 규칙이 데스크톱에도 걸린다. 데스크톱에서 검증한다.
- 렌더 뒤 다시 재고 그리는 후처리는 `queueMicrotask`/`requestAnimationFrame` 안에서 애니메이션 없이 한다.
  `setTimeout` 은 한 프레임이 먼저 찍혀 "그려진 뒤 다시 움직임"으로 보인다. 검증은 호출 수가 아니라 페인트 수로 센다.
- 전망 막대는 같은 보고서 선례 방식(같은 색 15% 채움 + 같은 색 1.5px 점선 테두리)이다.
  불투명도만 낮추거나 빗금(pattern-fill, CDN 에 모듈 없음)을 쓰지 않는다.
- 원본 플롯 안 글자(구분 라벨·패널 제목·주석·화살표)를 먼저 전부 목록화하고 하나씩 대조한다.
  데이터 라벨은 원본에서 점별 위치(맞출 쪽·거리)를 재고 웹 실측과 비교한다.
- 범례 HTML 에 넣는 속성은 Highcharts AST 허용 목록을 확인한다(`data-*` 는 기본 제거).
- 공용 파일 변경은 오너가 공통 수정을 요청했을 때만, fidelity-contract.md 의 공용 변경 프로토콜로 한다.

## 4. 본문·표·각주

- 본문은 DOCX 문단 본체 그대로 싣는다. 렌더러 정규식으로 자르지 않는다(「(그림 Ⅰ-N)」 절단 사고).
- 각주 번호는 원문 위치에 둔다(문단 끝으로 몰지 않는다). 팝업은 DOCX 각주 전부, ID 체계는 하나.
  검사는 "버튼이 가리키는 id = 내용 있음"과 "내용 = 어딘가에서 참조됨" 양방향으로 한다(MUST).
- 쉼표로 끝난 주 줄 다음 문단은 같은 주로 잇는다.
- 표는 DOCX `gridSpan`/`vMerge`/`tblGrid`(실제 열 폭)로 병합을 복원하고, 색만으로 값을 나타내는 칸은 색을 보존한다.
  들여쓰기는 `w:ind` 전체(left·firstLine·hanging·앞 공백), 구분선은 DOCX 테두리 종류·굵기로 판정한다.
- 같은 형식의 표는 기존 보고서 마크업·스타일을 따른다. 검증은 셀 단위로 짝지어 센다.
- 표·그림의 주·자료는 그 도표 컨테이너 안에 있어야 한다. 글자가 페이지 어딘가에 있다는 것으로 통과시키지 않는다.

## 5. 검수

- 완료 보고 전 6단계(원본 요소 대조·형제 전수·폭 전수·기준 출처·범위 명시·착지)는 bok-verify 에 있다. 하나라도 빠지면 "미확인"이다.
- 대리 지표(빌드 통과·스캐너 0건·DOM 존재·픽셀 유사도)로 "원본과 같다"고 말하지 않는다(MUST).
- 감사 결과가 0건이면 측정한 대상 수부터 본다. 목차 구간별로 먼 차트를 숨기는 보고서는 한 번에 재면 전부 0건이 된다:
  화면 높이씩 내려가며 재거나 차트마다 `scrollIntoView` 후 잰다. `scripts/audits/run-audits.mjs` 는 측정 0건을 실패로 본다.
- 폭은 1440·1024·768·390·360 전부. "창 줄이기"와 "그 폭으로 새로 열기"는 결과가 다르므로 둘 다 본다.
  폭을 바꾼 뒤에는 모든 차트의 `chartWidth` 가 바뀌었는지 확인한다(화면 밖 차트는 옛 폭으로 남는다).
- 모바일은 데스크톱 대비 y/x축 수·계열 수·보이는 계열 수를 먼저 스캔으로 비교한다. 사라진 축·계열은 코드에 의도가 없으면 결함이다.
- 회전한 x축 라벨 겹침은 외곽 상자가 아니라 "이웃 간격 × sin(각) < 글자 높이"로 판정한다.
  useHTML 범례는 SVG 항목 크기가 0이므로 `.highcharts-legend-item *` 까지 잰다.
- 지적 1건은 같은 원인을 전 차트에서 찾는 신호다. grep 과 브라우저 감사로 형제를 찾아 함께 고치고 잔존 0건을 보고한다.
  같은 장의 다른 그림은 같은 항목(음영·전망 표기·패널 수·기준선·플롯 글자·다중 우축·x축 형식·툴팁 단위)을 표로 대조한다.
- 확대해야 보이는 원본 흔적(1~2px 마커 등)은 구현 전에 오너 확인 목록으로 올린다.

## 6. 착지

- 착지 순서는 agent/* → feature → develop 이다. develop 에 직접 cherry-pick·push 하지 않는다(MUST). 절차는 ../../bok-land/SKILL.md.
- 착지는 작업의 일부다. 다른 세션 커밋을 기다리거나 남의 미커밋을 말없이 빼지 않는다.
- 공유 워크트리의 미커밋 파일마다 내용·수정 시각과 `git diff origin/develop -- <file>` 를 보고,
  이미 착지한 수정을 되돌리는 옛 상태인지 판정한다. 누구 것인지 모르면 단정하지 말고 오너에게 묻는다(MUST).
  같은 파일에 내 수정과 남의 미커밋이 섞이면 부분 커밋으로 남의 것이 빠진다는 점을 함께 알린다.
- 착지 확인은 패치 역적용 검사(`git apply -R --check`)로 한다. 한 줄짜리 큰 JSON 은 경로 단위로 3-way 대조한다.
- 공용 dev 서버가 다른 세션 편집으로 깨져 있으면 HEAD 에 내 변경만 얹은 별도 워크트리로 검증한다.
