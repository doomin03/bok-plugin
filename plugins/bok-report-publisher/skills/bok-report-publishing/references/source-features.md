# 원본 그림 특징 추출·대조와 피드백 루프

## 왜 필요한가

DOCX 의 통계 그림은 대부분 WMF/EMF **벡터 파일**이다(2026-09: 153개 중 140개).
눈금 숫자·범례 문구·주석 글자·선 색·점선 여부·음영 위치가 좌표째 저장돼 있다.
이를 PNG 로 바꿔 픽셀 유사도로 비교하면 작은 특징(기준선, 주석, 마커, 눈금 간격)이 점수에 묻힌다.
2026-09 오너 지적 252건 중 약 70%가 이런 시각 특징 누락이었다.

## 단계

1. **추출** — `start-report.py` 가 `figure-features.json` 을 만든다(단독 실행: `python scripts/extract-figure-features.py --source <docx> --out <json>`).
   그림·패널마다 `yAxes`(눈금·안쪽/바깥 눈금), `xLabels`, `xTicks`, `legend`(문구·표시 line/bar/line+marker/marker-only·색·점선),
   `series`(선 색·굵기·점선), `bars`(색별 개수), `bands`, `referenceLines`(값·점선), `verticalLines`, `notes`(플롯 안 글자),
   `markers`, `triangles`, `panelCount` 를 기록한다. 래스터(png/jpg)는 `raster-manual` 로 남아 사람이 채운다.
2. **연결** — 차트 계약의 `legendMatchCandidates`(범례 문구 ⊂ 시트 7행 계열 이름)와 `referenceImageCandidates`(본문 위치)를 함께 본다.
   둘이 같은 그림을 가리키면 확정 후보, 다르면 오너 리뷰 질문으로 남긴다. 추정으로 고르지 않는다(MUST).
3. **계약 채우기** — 확정한 그림의 특징으로 `visualContract`(yAxes·xAxis·seriesAppearance·legend·annotations)를 채운다(MUST).
   빈 칸이 남으면 `pending` 이다.
4. **대조** — 구현 후 `node scripts/verify-figure-features.mjs --features <json> --map <figure→차트 id> --url <보고서> --widths 1440,390 --out <dir>`.
   Highcharts 가 실제로 그린 축 눈금·라벨·범례·계열·음영·기준선·글자를 원본 특징과 항목별로 비교해 `figure-check.json/md` 를 쓴다.
   `--map` 은 오너 리뷰에서 확정한 연결을 쓴다. 자동 연결(범례 60% + 눈금 40%)은 후보 찾기용이다.
5. **오너 예외** — 오너가 일부러 원본과 다르게 정한 것(예: X축 「25」 삭제, 원본 오타 「좌측」→「좌축」)은
   `--exceptions` 파일에 `{chart, feature, reason, ticket}` 로 적는다. 결과에 `accepted` 로 남고 숨기지 않는다.

## 현재 정확도와 한계 (2026-09 측정, 그대로 보고할 것)

- 원본에서 읽는 값(글자·눈금·색·선·음영 좌표)은 정확하다. 해석(패널 나누기·범례 위치)은 아직 틀릴 수 있다.
- 수정 전 develop(1b01ff6)에 돌리면 BOKM-709·744(축)·757(음영 기간)·761·728·737(범례 문구)을 자동으로 잡았다.
- 남은 실패 29패널 중 진짜 차이는 일부다. 잡음 원인: 세로·가로로 붙은 다중 패널, 플롯 틀 안 범례, 축 옆 데이터 라벨,
  빗금 전망 막대(음영으로 오인), 문자셋이 틀린 그림. **실패 목록은 합격 판정이 아니라 검토 목록이다(MUST).**
- 비교하지 않는 것: 툴팁, 데이터 값(원본 셀 대조로 따로 검증), 각주 본문, 모바일 배치. 보이는 눈금 라벨 숨김(showLastLabel 등)도 아직 못 잡는다.

## 피드백 루프 (오너 지적 → 재발 방지)

오너 지적 하나를 처리할 때 아래를 모두 한다(MUST).
1. **분류** — 지적을 특징 유형(축·눈금 / X축 라벨 / 범례 / 계열 표시 / 음영 / 기준선 / 플롯 안 글자·화살표 / 패널 / 툴팁 / 각주 / 데이터 / 모바일)으로 트래커에 적는다.
2. **고치기** — 원본 특징·3월 실측·공용 헬퍼를 근거로 고친다.
3. **형제 전수** — 같은 유형의 실패를 `figure-check` 결과와 grep 으로 전 차트에서 찾아 함께 고친다. 잔존 0건을 보고한다.
4. **검사기 보강** — 대조기가 이 지적을 못 잡았다면 `figure-compare.mjs`(또는 추출기)에 규칙을 더하고, `test_figure_features.py` 에 사례를 더한다.
   규칙을 문서의 MUST 로만 남기지 않는다.
5. **예외 기록** — 오너가 원본과 다르게 정한 것이면 예외 파일에 적어, 다음 검사에서 다시 실패로 뜨지 않게 한다.
6. **소급** — 새 규칙은 이미 처리한 같은 유형 항목에도 다시 돌린다.
