# 각주 연결과 원본 UI·반응형 검증 계약

준비·구현·검증 단계에서 이 계약을 읽는다. 문서 추출, 빌드 성공, 이미지 점수만으로 적용 완료를 선언하지 않는다. 실제 대상 프로젝트에서 검증하지 않은 항목은 pending이다.

## 문서 각주 → 본문 클릭 → 원문 표시

1. `document.json`의 `inlineParagraphs`와 `noteLinks`로 본문 문단 내 참조 위치를 찾고 `notes.footnotes`/`notes.endnotes`의 동일 sourceId와 연결한다. sourceId는 내부 키이며 표시 번호가 아니다. 원본 렌더링과 `word/settings.xml`, 절별 `sectPr`의 번호 시작·재시작·형식, 사용자 지정 기호를 확인해 `displayLabel`을 확정한다. 4개의 문장을 전달받았다고 임의로 1~4번을 붙이지 않는다.
2. 각 참조에 `{noteType, sourceId, sourceBlock, paragraphIndex, tokenIndex, displayLabel, targetComponent, triggerId, contentId, sourceText}`를 기록한 `note-map.json`을 evidence에 만든다. 각주 없는 선택 범위는 원본 확인 근거와 함께 N/A로 기록한다. 같은 번호가 절마다 반복되어도 report/section/type/id를 포함한 연결 키로 충돌을 방지한다.
3. 기존 사이트에서 실제 사용하는 본문 각주 트리거, 각주 데이터 등록, 팝업/툴팁/패널 컴포넌트와 닫기·포커스 처리 소스를 찾는다. 경로·해시를 기록하고 같은 구조와 API로 새 보고서 내용만 연결한다. 차트 하단 `.chart-footnote`, 표 하단 `.table-footnote`, Highcharts 데이터 툴팁과 본문 각주 클릭 UI는 서로 다른 대상이다.
4. 클릭 시 문서 각주 전문을 표시한다. 수치·부호·화살표·단위·문장 순서·문단·명시적 줄바꿈을 보존한다. 요약하거나 기존 보고서 각주 문구를 남기지 않는다. 추출 텍스트에 없는 표·이미지·링크·강조는 원본 XML/관계 파일로 확인해 기존 지원 구조로 구현하고, 미지원이면 pending으로 보고한다. 임의 HTML 삽입을 피하고 기존 안전한 렌더링을 사용한다.
5. 원문 연결 실패·중복 ID·실제 표시 번호 미확정이면 구현 완료로 처리하지 않는다. separator/continuationSeparator 같은 문서 내부 항목을 각주로 표시하지 않는다. 본문 번호 위치를 추측해 문장 끝으로 옮기지 않는다.
6. 브라우저에서 선택 범위의 **모든 각주**를 실제 클릭/터치해 열린 UI의 텍스트를 sourceText와 대조한다. 비교 시 공백 정규화는 레이아웃 공백에만 적용하고 숫자·기호·문장을 제거하지 않는다. 반복 참조, 번호 재시작, 다른 각주로 전환, 닫기/재열기, 키보드 접근과 포커스 복귀, 라우트 재진입을 확인한다. 모바일·태블릿·PC에서 오표시·잘림·화면 밖 팝업이 없는 증거를 남긴다.

## 기존 구조·스타일 보존

- 대상 사이트의 page/report/section, 본문·제목, LazyChart, chart-wrap, table-wrap/table-scroll/depth-table, 이미지 및 각주 UI를 먼저 확인한다. docs의 비교 프로젝트가 별도 저장소여도 대상 사이트의 기존 공통 UI 계약을 대체하지 않는다.
- 기개발 소스와 대상 공통 SCSS·차트 유틸·공유 컴포넌트는 변경 전 해시와 Git 차이로 보존을 검사한다. 사용자 기존 수정과 이번 작업의 변경을 구분한다. 검증 통과를 위해 원본 해시를 다시 쓰지 않는다.
- 표는 원문의 행/열, 셀 병합, 헤더 단계, 단위, 주석·출처와 기존 모바일 스크롤 구조를 유지한다. 페이지 전체 가로 넘침, 헤더/셀 정렬 불일치, 잘린 수치가 없어야 한다. 임의 카드 전환이나 새로운 전역/인라인/scoped 스타일로 우회하지 않는다.

## 차트 원본 비교 계약

각 그림의 원본 이미지, XLSX 셀 범위, 기개발 소스를 함께 확인하고 아래 값을 차트 spec 또는 evidence의 비교표에 기록한다. 미확인 값을 추측하지 않는다.

`chart-spec.template.json`의 visualContract를 채운다. yAxes에는 실제 사용 축마다 side/unit/min/max/tickInterval/titlePlacement/sourceEvidence를, seriesAppearance에는 계열별 type/color/dashStyle/marker/axis/order를 기록한다. 미사용 축은 근거와 함께 N/A로 명시한다. viewport별 실제 containerWidth, screenshot, 결과와 breakpoint 경계 증거를 추가한다. audit-chart.mjs는 이 시각 계약의 실행 결과를 검증하지 않으므로 브라우저 검증 증거가 별도로 필요하다.

| 대상 | 원본 대비 확인 항목 |
| --- | --- |
| 좌/우 Y축 | 단위 문자열·기준연도, 소수 자릿수·부호, min/max·간격·0선, 계열별 축 연결, 단위 제목 위치·정렬·여백 |
| X축 | 날짜/범주 의미, 기간·빈도, 눈금 위치·표시 문자열·생략 기준, 회전·줄바꿈, 양끝 라벨 |
| 계열 | 이름·개수·순서, line/column/area/range 등 유형, 색·선 두께·점선·마커, 누적·좌우 축, null·예측 구간 |
| 범례·주석 | 항목 순서·줄바꿈·정렬·위치, 주석/화살표/음영/전망 경계, 제목·자료 출처·그림 주 |
| 실제 값 | Highcharts 런타임의 각 계열/포인트를 원본 셀과 대조, 단위 변환·혼합 빈도·범위/누적 의미 |

스크린샷과 동일한 수치 의미·단위·계열·표현을 목표로 하되 폰트 렌더링이나 반응형 재배치를 픽셀 일치로 판단하지 않는다. 원본 데이터와 그림이 상충하면 충돌을 보고한다. 작은 화면에 맞추기 위해 단위·계열을 지우거나 허위 min/max로 데이터를 자르지 않는다. 기존 responsive.rules, 공유 모바일 함수와 차트 resize/reflow 구조를 먼저 재사용한다. 필요한 조정은 새 차트의 허용된 옵션 범위에서 근거를 남긴다.

## 기기별 필수 검증

기존 프로젝트의 실제 SCSS/Highcharts breakpoint를 읽는다. 대표 viewport는 모바일 375×812, 태블릿 768×1024 및 가로 1024×768, PC 1440×900이다. 기존 분기 경계 전후 1px도 확인하고 각 viewport와 **실제 차트 컨테이너 너비**를 기록한다. 기존 breakpoint를 새로 정의하지 않는다.

각 크기에서 원본·기존 구현·새 구현을 대조하고 캡처한다. 리사이즈 후 reflow, 지연 로딩/숨김 컨테이너 표시, 라우트 이탈·재진입, 중복 차트 인스턴스·이벤트, 터치/툴팁을 확인한다. 축 단위·라벨·범례·주석의 겹침/잘림, 표의 스크롤, 각주 팝업 표시도 확인한다. 원본 이미지 없는 항목은 시각 일치 pending으로 남긴다.

`evidence.md`에 항목/viewport/원본 근거/관찰 결과/pass·fail·pending/캡처 경로/미해결 차이를 표로 기록한다. 비교 HTML·MD는 image-comparison.md 절차로 생성하며 계열·축·단위별 분석을 채운다. 실패 수정 후 영향받은 크기와 기능을 재검증한다. 모든 해당 검사가 pass이고 오너가 결과를 확인한 경우에만 accepted로 기록한다. 스크립트가 이 문서의 브라우저 검증을 자동 수행한다고 보고하지 않는다.
